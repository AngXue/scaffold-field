# 固定大图性能项目

这些输入在 `803ba54` 独立旧引擎与当前引擎上逐字段对照后冻结。`manifest.json` 固定输入和旧版完整输出的 SHA-256。它们是测算项目输入，不包含规则代码或可执行指令。

| 项目 | 输入构造 | 验证规模 |
| --- | --- | --- |
| orthogonal-50 | 25 个独立 L 形，每个两段为3.60m和5.40m，3层；按16m网格隔开 | 50段、300立杆、1950标准管、750片钢笆 |
| orthogonal-200 | 同样构造，100个L形 | 200段、1200立杆、7800标准管、3000片钢笆 |
| multi-elevation-24 | 12个L形，交替落在0.00、3.50、5.64m；较高落脚面为10×10m体块顶面，线段离边缘至少2m | 24段、144立杆、936标准管、360片钢笆 |

所有线段均水平或垂直。每个L形的原始周长为9.00m，因此总周长依次为225.00、900.00、108.00m。每个L形的直线站位为3站与4站，转角共用一对，实际12根立杆，固定25／100／12份可独立核对立杆总数。体块与架体之间保留足够间距，三图必须没有问题且允许出量，不能因无效图提前退出而获性能优势。库存、排距和其他默认值均已写入JSON，未来修改默认参数不会改变固定输入。

复现：`npm run test:parity` 包含原23图和这3图；`npm run bench:rules` 同时检查完整输出、源输入不变、常用图、大图及多标高耗时和内存。屋顶小图预热1500次，每样本批量20次后取每次平均；其余预热10次，每样本1次；均100个旧新交替的配对样本。

内存另开旧／新独立Node进程，各预热10次并计算100次，每次测量前垃圾回收。主门槛读取操作系统的进程RSS高水位，包含引擎加载成本。报告另列调用结束时观测的最大堆占用，但不把它冒称为堆峰值或分配总量。内存子进程按顺序运行，不与耗时采样争抢资源。Node测量不代表安卓WebView的内存或帧率；真机验收仍按后续平板计划。
