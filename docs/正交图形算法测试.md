## 修复前复现记录

优先级表示修复顺序，不是结构安全评级。坐标均为平面 `(x, z)`，单位 m，默认参数除非另有说明。

### 1. 闭环首尾转角遗漏，数量依赖起点

最小常规案例是 `rectangle-in`：`(0,0) → (7.2,0) → (7.2,4.8) → (0,4.8) → (0,0)`。

起点处应与其余转角一样处理，但偏移排 `(0.9,0.9)` 没有角柱。反向绕行的 `rectangle-out` 则漏掉 `(-0.9,-0.9)` 的外侧交点、该角的纵向延伸和铺板角块。

更直接的材料证据来自 `closed-l`：

```text
(0,0) → (7.2,0) → (7.2,3.6) → (3.6,3.6)
      → (3.6,7.2) → (0,7.2) → (0,0)
```

保持边、方向和参数完全相同，只把起点移到第四个顶点 `(3.6,3.6)`：

| 材料 | 从 `(0,0)` 起画 | 从 `(3.6,3.6)` 起画 |
| --- | ---: | ---: |
| 立杆 | 35 根 | 33 根 |
| 钢笆 | 165 片 | 160 片 |
| 十字扣 | 584 个 | 540 个 |

原因位于 `scaffold.ts` 的转角遍历：`junction + 2 < physical.length` 只处理线性数组中的相邻两段，没有处理末段接首段。`pathIsClosed` 已用于端部防护，但转角生成没有共享闭环拓扑。

修复应让首尾接缝参与完整的转角流程，包括角柱、删柱、纵向延伸、栏杆、槽钢和角块，随后验证换起点的材料数量一致。不能仅在最后补一个角柱。

### 2. 在直线上加节点会漏横向杆

对比 `line` 与 `line-split`：

```text
一段：(0,0) → (7.2,0)
两段：(0,0) → (3.6,0) → (7.2,0)
```

两种输入的立杆站位相同，都是 10 根立杆；但横向杆从 **30 根变成 24 根**。中间站位的 5 个作业层和 1 个扫地杆层各漏 1 根。没有提示。

原因是 `isInternalPathNode` 将所有中间节点都当作转角略过横向杆；共线时并没有邻段纵向杆替代它。此例还改变了分段选管和扣件数（十字扣 174 → 180），因此本轮只断言明确缺失的横向杆，没有假定任意共线拆分必须保持全部采料组合不变。

### 3. 窄 U 形产生重合实体

`width-u`：`(0,0) → (4.8,0) → (4.8,0.9) → (0,0.9)`，间隙正好等于默认排距。

输出共 126 根物理管，其中 **36 根与已有管的两个端点完全相同**，忽略端点顺序后仍相同。它们被重复绘制和计入库存管数量。仅有“末跨 0.90 m”提示，没有架体带重叠提示。

检查的是完整同位置实体，不是端头相接、不同高度交叉或普通管端富余。立杆去重和局部转角处理不能覆盖两条远端平行腿的重合。后续需先确定这种窄轮廓的处理规则：拒绝/提示架体带冲突，或建立共用杆件；仅隐藏重合模型会留下材料重复。

### 4. 短边生成只连一条腿的角柱

`short-start`：`(0,0) → (0.5,0) → (0.5,4.8)`。

算法在 `(-0.4,0.9)` 增加角柱，但该柱在第一作业层只连接第二段纵向杆，第一段没有达到它。末边只有 0.5 m 的 `short-end` 也有对应问题。

原因是 `offsetRowCrossing` 的 `meetsAtTheEnd` 将这种“交点落到短段起点之前”的情况放行，随后按角外延伸处理，但实际延伸只处理进段末端与出段起端，无法让两条腿都接到该柱。现有短跨提示没有指出连接缺失。

修复需区分普通内角、普通外角与短段不足，不能把所有 `inside === false` 的情况都归入外角。

### 5. 新增、合并角柱后，相邻接头会同高

`short-end`：`(0,0) → (7.2,0) → (7.2,0.5)`。

同一纵向杆上相邻两根立杆，平面位置为 `(5.4,0.9)` 和 `(6.3,0.9)`，对接接头都在 **6 m**，相差 **0 mm**，不符合本项目要求的至少 500 mm 错开。

`short-start`、闭合凹形和部分连续折线也触发。检查器按真实纵向杆上连续的两根立杆判断相邻关系，再比较各自实际对接扣的高度，未把不相邻的任意两柱拿来比较。

原有 `(row + station) % 2` 在简单直线有效，但新增角柱、删柱与共点合并会改变最终邻接关系。后续应对生成后的立杆邻接关系分配/验证选管组合；奇数邻接环也不能只依赖两组序列机械交替。当时仅覆盖纵向相邻柱；修复后的检查也覆盖横向杆连接的对排关系。

### 6. 内转角钢笆面积重复累计

`l-inside`：`(0,0) → (7.2,0) → (7.2,4.8)`。

第一层钢笆矩形面积相加为 10.8 m²，但平面并集为 **9.99 m²**，角部 0.9 × 0.9 = **0.81 m²** 被算了两次。默认 5 层的 `deckArea` 为 **54 m²**，实际几何并集面积合计 **49.95 m²**，多 **4.05 m²**。

这不是正常的 100 mm 钢笆搭接：当前 `decks[].corners` 已把每一跨按片数划分成互不重叠的覆盖小块，搭接影响的是片数；重复来自两段各自的整个转角覆盖区。普通直线校验未触发，检查器也用重叠、包含、相接和分离矩形验证了面积并集计算。

原因是各段独立生成覆盖面，`calculateMaterials` 再直接累加 `deck.area`。按当前“面积 = 实际几何覆盖面积”的约定，应消除重复面积。钢笆片数是否也应减少，需要明确转角铺片/裁切策略，不能根据面积比直接扣片数。

### 7. 自交与原路折返输入仍返回普通估算

`backtrack`：`(0,0) → (4.8,0) → (0,0)`，产生 12 根完全重复的管，警告列表为空。

`crossing`：`(0,0) → (4.8,0) → (4.8,4.8) → (2.4,4.8) → (2.4,-2.4)`，路径穿过已有线段，警告列表也为空。

这两张图特意作为输入边界，不代表正常搭建方案。需要独立检测非相邻线段交叉、共线回头/重叠，再明确支持或提示用户修改。该检查的结果是缺少输入语义提示，不是在推导新的交叉架体搭建规则。

## 未发现异常的项目及限制

在本轮输入范围内，未发现周长不符、非有限管端/扣件坐标、物理管长与库存规格不符、完全同位置的扣件、柱底没有槽钢，或“库存根数 / 钢笆片数 / 十字扣数 / 对接扣数”与生成实体数量不一致。

这些通过项只证明内部一致。例如重复管同时进入实体和材料表时，两边仍然相等，不能据此认定材料正确。基础检查只验证柱底在槽钢投影跨度内，未验证槽钢之间的碰撞；管重合只检测完全相同的端点，未穷尽局部重合和实体穿插。没有把反向绘图当作等价变换，因为当前偏移始终在路径左侧，反向会改变架体所在区域。

批量检查针对领域算法，图册以算法输出绘制。浏览器人工验证选取代表性闭合轮廓，不声称 642 组都经过人工三维交互或安卓设备测试；未进行结构验算。

## 本次修复与验证

1. 闭环末段→首段执行完整转角流程，按轮廓固有边长/转向选择稳定遍历起点；补上整跨数量的浮点容差。闭合 L 形从任一顶点起画，默认均为 **34 根立杆、140 片钢笆、540 个十字扣**。
2. 共线中间节点保留横向杆，共用直杆在选管前合并。7.2 m 直线拆成 3.6 + 3.6 后与整段均为 **30 根横向杆、102 根库存管、174 个十字扣**。
3. 交点超出短内角的可连接范围时，保留原站位和横向杆并提示，不再生成异常角柱。审计通过实际 `cornerJunctions` 识别角柱，避免把恰好落在交点上的普通站位柱误报为角柱。
4. 同线重叠的横、纵杆共用实体，保留连接用途；按最终生成杆件统计扣件。默认窄 U 形的完全重复管数量为 **0**，同时提示架体带重叠。
5. 按最终立杆邻接关系修复接头组合，使用动态规划避开相邻接头；库存不足时明确提示。标准库存下全部 642 组均满足本轮错开检查。
6. 使用凸多边形差集划分钢笆实际覆盖面；优先由进段覆盖内转角，再处理多段重叠并补齐覆盖空洞。一片的多个裁切面仍只算一片，完全被覆盖的片移除；默认内 L 形五层 **49.95 m²、65 片**。
7. 自交、原路折返、非相邻架体带重叠分别给出路径/布置提示。警告保留在结果中；专项检查通过表示该情况已被处理或明确提示，不表示这些输入已成为施工方案。
