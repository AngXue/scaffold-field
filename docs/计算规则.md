# 架算 · 计算规则与领域约定

这份文档是**架算（Scaffold Field）计算口径的唯一说明**，同时给现场核对用。规则全部实现在
[src/domain/scaffold.ts](../src/domain/scaffold.ts) 里，并由
[src/domain/scaffold.test.ts](../src/domain/scaffold.test.ts) 逐条钉住；**改规则时必须三处同步**：
代码 → 测试 → 本文档（见文末《规则变更流程》）。

阅读方式：每条规则的「为什么」写在引用块里；数值示例统一用默认参数
（作业层数 5、步距 1.88 m、排距 0.9 m、立杆纵距 1.8 m、钢笆片 0.95 × 1.2 m、栏杆根数 1）。

---

## 1. 高度与作业层

| 项 | 规则 |
| --- | --- |
| 唯一高度输入 | **作业层数 n**（默认 5）。没有「搭设高度」输入，高度全部由它推出来 |
| 作业层标高 | 第 k 层 = k × 步距。**第一层就是一个完整步距**，不是「扫地杆 + 步距」 |
| 理论搭设高度 | `T = 0.3 + 步距 × n` |
| 内侧（靠墙）立柱 | `T` |
| 外侧（带栏杆）立柱 | `T + 步距 + 0.3` |
| 开口端端柱 | 两端都按外侧高度（端头没有墙，两侧都是临边） |

> 0.3 m 是**顶层立柱的固定延伸长度**（`TOP_POST_EXTENSION`），永远加在顶端，不是起始偏移；
> 它是常量而不是参数。外侧那多出来的一个步距，是为了在顶层作业层之上再拴一道栏杆。

示例（n = 5）：作业层 1.88 / 3.76 / 5.64 / 7.52 / 9.40 m；T = 9.7 m；内侧立柱 10 m、外侧 12 m。

## 2. 平面与两排立柱

- 2D 比例固定 **50 px/m**，路径是一条折线（`Point2D[]` + 每段实测长度）。
- 架体永远是**两排立柱**：`row 0` 沿路径、`row 1` 沿路径偏移一个排距。
- 排距默认 **0.9 m**；选择钢笆片宽度时自动写为 `宽度 − 0.05 m`（仍可手改）。
- 立杆纵距是**上限**：先按每段 `ceil(段长 / 纵距)` 等分。角柱距中间站位不超过 0.25 m 时，若移动后两侧跨距仍不超过纵距，就把整站移到角柱处；两排、横杆、槽钢和钢笆分跨一起移动，图纸端点不变。0.25 m 是站位协调范围，不是把附近任意两根柱子合并的距离。短跨仍给出复核提示。
- **内侧位置**（路径侧 / 偏移侧）决定哪一排是外排；只有外排带防护栏杆、并且更高。
- 重合节点自动去重；两段共用的角柱只算一根，取更高的那个高度。
- **连续短折返按实际延伸范围判断转角**：短边的另一端已由凸角延长时，内转角交点可使用这段已有延伸；不再因为交点超出原始短边就额外保留整排端柱。偏移排在两个角柱之间布柱，越过内转角交点的原站位不再设偏移排立柱。原端点仅落在角柱内侧 0.25 m 以内、且另一端凸角已承接整段并满足纵距时，也省去该冗余端柱。
- 只有两腿实际可达才合用角柱；没有邻接延伸可用的独立短边仍保留站位并提示。槽钢若不再承托立杆，或它承托的全部立杆已由另一根承托更多立杆的槽钢承接，则移除该冗余槽钢。
- 回归图 `user-short-returns`（24.20 m 闭环，含 0.7 / 0.8 m 短边）在排距 0.9 m 时为 **45 根立杆**；原来的 50 根包含 5 根转角与站位冗余。钢管和扣件按最终实体重新统计。
- 闭合路径的末段与首段使用相同的转角规则；绘图起点不改变实体或材料数量。站数在整跨边界容忍浮点误差，避免 3.6 m 因舍入被分成 3 跨。
- 自交、共线重叠和原路折返明确提示调整路径；不为交叉区域新增未确认的构造规则。非相邻段的架体带重叠时单独提示复核布置。

## 3. 水平杆

**纵向水平杆**：两排立柱各一道；`钢笆纵向杆数 > 2` 时在中间加**填芯**（钢笆纵向支承杆），
填芯只出现在真正铺板的楼层。

**横向杆**：每个立柱站位一道，跨过排距；**不加管端外伸**——现场买的是 1.2 m 管，多出的部分
由组合居中溢出，正好让横杆两端挑出立柱。只有**已成功处理的转角**省略该站横向杆，因为那里
已被另一段纵向杆跨过。共线中间节点保留一道横向杆；无法自动处理的短边转角保留原站位与横向杆并提示。

**转角处的纵向水平杆**：每一段的**所有排**（内排、外排、填芯）都延伸到**另一段偏移排线**的交点，
所以同一段的三排长度一致、采购组合一致：

| 段 | 每排长度 | 组合 |
| --- | --- | --- |
| 7.1 m | 8.20 m（7.1 + 0.9 排距 + 0.2 两端外伸） | 6 + 2.4 |
| 4.3 m | 5.40 m（4.3 + 0.9 + 0.2） | 6 |

> 两段的填芯因此会在角块中心**十字相交**——现场就是一只转向扣的事（本模型不单独计转向扣），
> 不允许用「让一根提前收头」来回避：那会让那一排明显比其他排短、看着不对齐。

## 4. 钢笆片（脚手板）

- 规格可选：长 **1 / 1.2 m**，宽 **0.75 / 0.8 / 0.95 m**；宽边跨排距、长边沿架体。
- 片与片接头**搭接 100 mm**，所以每加一片只多出「片长 − 0.1」的覆盖，片数按
  `ceil((跨长 − 0.1) / (片长 − 0.1))` 计算（横向同理）。
  例：1.2 m 跨 1 片；2.0 m 跨 2 片（1.2 m 片）或 3 片（1 m 片）；2.4 m 跨 3 片。
- 铺板间隔：默认每层铺（`钢笆铺设间隔 = 1`）。
- **凸角角块**：每个铺板层的角块（0.9 × 0.9 m，四边分别由两段的横向方向杆件与两段外排延伸围成）
  补一片**裁切钢笆 0.81 m²**，平台绕过建筑物阳角连续。
- 材料表口径：**片数 = 实际铺设片数**；**面积 = 实际几何覆盖面积**（裁切片按实际面积，不按整片）。
- **内转角重叠区归进段**，出段面按实际覆盖裁切；其他多段重叠区只保留一次覆盖，且不得产生空洞。完全被覆盖的片不再计数，部分裁切的片仍计 1 片，不按面积比例折算片数。
- `DeckPanel.corners` 的插值坐标保留 6 位小数，避免半毫米边界在换绘图起点时提前舍入成不同的片框；面积汇总仍按原精度输出。`DeckPanel.corners` 保留原片覆盖框，`coverage` 保存该片裁切后的面；一片即使裁出多个面仍只计一次。三维、俯视图和 `area` 使用这些相同的裁切面，避免同层重叠闪烁。示例 7.2 + 4.8 m 内转角默认五层覆盖面积为 **49.95 m²**、钢笆 **65 片**。

## 5. 防护栏杆

- 只在**外排**，且**不可关闭**；唯一的开关是「内侧位置」（选哪边是外侧）。
- 栏杆根数（参数）：
  - **1（默认）**：一道，居中于步距 → 顶层作业层上方 0.94 m（随步距变化）；
  - **2**：按 JGJ 130-2011 §7.3.12 —— 上栏杆上皮 **1.2 m** + 中栏杆**居中**。
- **顶层比下面每一层多一道**：多出的是**架顶栏杆**，位置 = `理论搭设高度 + 步距`
  （默认 **11.58 m**，即外排柱顶下方 0.3 m 的固定延伸处）。这正是外排高出那一个步距的用途。
- **开口端折返**（端部防护）：每个开口端在每道栏杆标高设一道折返栏杆（JGJ 80-2016 §4.1.1，强制性条文）。
- 栏杆只拴在立柱上：某道栏杆高过它所在排立柱顶时会**删除并告警**（`top-rail-height`），绝不悬空。
- **材料表不单列「防护栏杆」**：栏杆就是同规格钢管，计入钢管总长；`materials.guardrail`
  只用于测试与诊断。栏杆在 3D 里单独一层，便于单独查看。

## 6. 立杆接头错开

- 相邻立柱的对接接头**不得在同一高度**，错开 ≥ **500 mm**（JGJ 130-2011 §6.3.6）。
- 实现：按 `(排 + 全路径站号) % 2` 分奇偶；偶数用最省组合，奇数先用「同管倒序」
  （6+4.5 ↔ 4.5+6），倒序无效时（如 6+6）改用**总长也不同**的次省组合
  （11.88 m 立柱：6+6 = 12 m 旁边是 2.4+6+4 = 12.4 m），三层 3D 里一眼能看出两根不一样高。
- 转角处的**角柱**取进段末站的**相反奇偶**，于是外排绕角一圈是
  `…6+6、2.4+6+4、6+6、2.4+6+4…`。
- 上述奇偶是优先组合。增删角柱、合并共点和共用杆件之后，按**最终纵向杆与横向杆上的相邻立杆关系**再检查实际接头高度；存在冲突时重新选管，同时避开已经选定的相邻柱接头。闭环和奇数邻接环不局限于两组序列。
- 修复选管按「根数、满足错开且尽量总长不同、总长」的顺序选择，保留库存规格；按根数和累计高度做动态规划，不枚举所有排列。若现有规格无法错开，则明确给出 `splice-stagger-*` 提示，不伪造管规格或移动接头。

## 7. 转角处理

按两段偏移排的位置分三种情形（交点 = 两条偏移排线的交点）：

| 情形 | 处理 |
| --- | --- |
| 共线 | 立柱共用，保留一道横向杆；同线连续纵杆共用 |
| **反向转角**：偏移排落在角**内侧**（内置示例 7.2 + 4.8） | 两条偏移排在段内相交 → 两根近角柱**并成一根斜接柱**（净省 1 根）；斜接柱也有自己的槽钢；交点上的杆件交叉计入十字扣 |
| **同向转角**：偏移排落在角**外侧**（平板上的 7.1 + 4.3） | 两条偏移排各差一个排距才相交 → 两根近角柱**保留**（它们挑住延伸段），两段的排全部延伸到交点，**补一根角柱**（+1 根），补一片角块钢笆，槽钢只保留一个方向 |
| 短内角的交点落在进段起点之前或出段末点之后，或交点过远 | 不当作外角延伸；保留原站位与横向杆，不新增只连一条腿的角柱，并给出 `short-corner-*` 提示 |

闭合轮廓的末段→首段也完整执行上表，包括角柱、删柱、纵杆延伸、栏杆、槽钢和角块。

## 8. 扫地杆与槽钢

- **扫地杆层**：默认高度 0.2 m（JGJ 130-2011 §6.3.2 的上限，超过会告警）。它只有普通横向杆与
  纵向杆，**没有钢笆、没有填芯**；它不属于作业层（层号 0）。
- **槽钢**：每个立柱对一根，方向与横向杆一致、长度与横向管相同（买整根，不从钢管切）。
- 转角处槽钢**只保留一个方向**：出段首站不放（否则与进段末站交叉），角部那根在进段方向上
  跨两根角柱。示例：**6 根横向 + 3 根纵向 = 9 根**。

## 9. 钢管与扣件

- 库存钢管规格：**0.8 / 1.2 / 2 / 2.4 / 3 / 4 / 4.5 / 6 m**。
- 组合规则：取 **≥ 需要长度的最省组合**（对接扣件对接，`搭接长度 = 0`，段与段端对端，
  每个接头一只对接扣）。设置搭接 ≥ 1 视为搭接，本模型不建模并给出告警。
- 管端外伸默认 **0.1 m**（纵向杆两端；横向杆没有）。
- 同高度同一直线上重叠或相接的同类直杆，在定尺组合之前合并；纵杆与横杆占据同一条实体管时也共用，保留两种连接用途。共用管只组装、渲染、计料一次。它不改变二维测量分段和周长，也不把相互垂直或不同高度的管合并。
- 扣件按**实际连接的两根杆件**计数，同一杆件对只计一次，不直接把站位点当作扣件。
  - 普通主节点：纵向杆—立杆、横向杆—立杆各 1 只十字扣，通常合计 **2 只/主节点**。
  - 填芯支承杆：只在实际存在横向杆的交点计 1 只十字扣；转角省掉横向杆的位置不计。
  - 栏杆及端部折返：每根栏杆与每根实际穿过且够高的立杆连接时计 1 只十字扣。
  - 转角：不再给移走的近角立杆计扣件；角柱与各条实际穿过它的纵杆、栏杆分别计数。
    立杆能否承托栏杆以**定尺管组合后的实际柱顶**为准。
  - **对接扣**：每根逻辑杆的物理钢管段数减 1，一接头一只套筒；默认搭接长度为 0。
  - **转向扣**不建模（显示 `--`），包括转角填芯交叉、剪刀撑和搭接所需的转向扣。
    因此已计算的十字扣与对接扣之和并非整套架体全部扣件的最终采购数量。
  - 按 **30 个/包**换算，包数由实际显示数量（含手工修正）向上取整。
  - 材料页扣件每次手动增减 **1 包（30 个）**；不足 1 包的剩余数量减少后归零，不保存隐藏负数。内部修正、保存与 CSV 继续用「个」记录，兼容旧版按个修正的数据；界面同时显示个数、包数和原计算值。
- 三维扣件使用低面数的双抱箍（十字扣）、长套筒加螺栓（对接扣）形状，按关联钢管轴线定向；
  转向扣保留双抱箍加中心转轴的渲染能力，但不会为未建模的连接生成数量或零件。
  这些外形用于辨认类别，不是供应商的精确加工模型。
- **本应用只估数量，不做采购与结构验算**：不给截面特性、牌号、重量。

## 10. 参数、持久化与迁移

- 面板常显：作业层数、钢笆纵向杆数、扫地杆高度、栏杆根数、内侧位置；
  其余（排距、立杆纵距、步距、管端外伸、搭接长度、铺板间隔、钢笆片尺寸）收在「更多参数」。
- localStorage 键：
  - `scaffold-project`：当前项目（保存按钮写入）；
  - `scaffold-default-demo`：默认示例（「设为默认示例」写入，「重置为默认示例」回到它）；
  - `scaffold-history`：历史记录，**最多 100 条**（超出丢弃最旧的）。

**历史记录**（顶栏「历史」按钮，右上角数字是条数）：

| 操作 | 说明 |
| --- | --- |
| 保存 / 存入当前 | 把当前图纸 + 参数 + 手工修正存成一条记录；与最新一条完全相同时不重复添加 |
| 使用 | 用该记录覆盖当前状态（此后显示「有未保存更改」，是否写回项目由「保存」决定） |
| 删除 | 删掉这一条；超过 100 条时自动丢弃最旧的 |

记录标题自动生成：`段长合计 · 作业层数 · 排距`，下面一行是保存时间，便于现场区分不同方案。
- 迁移：`rowCount → deckSupportRailCount`、`height → layerCount`；`guardrailSides` 已废弃并丢弃。
- 手工修正数量是**增量（delta）**而不是绝对值覆盖，参数变化后修正继续生效。
- 标准钢管列出全部默认库存规格（含计算值为 0 的规格）。按**修正后显示数量**分组：大于 0 的在前，0 根的在后；组内按长度从长到短排序。零规格手动加量后立即参与前组排序，恢复为 0 后回到末组。
- 钢管栏总根数与 CSV 采用同一份修正后列表，包含手动添加的原零数量规格；原计算值仍可见。修正不会改变三维构件或理论钢管长度。

## 11. 明确不做的范围

- 密目式安全立网、安全平网、**挡脚板**（按要求移除）；
- 连墙件、剪刀撑（未建模、不渲染，规则待现场给）；
- 扎丝 / 小垫板 / 支模板 / 剪刀撑：列表里以 `--` 显示，可手工填写，永不自动给数；
- 结构安全验算：本应用只做现场测量与材料估算。

---

## 12. 界面与 3D 约定（简述）

- **2D**：无边界平面，平移缩放只是视图变换；每段同线宽同颜色，选中用光晕而不是加粗。
- **3D**：渲染 `pipeSegments` / `decks` / `connectors`；点击零件优先于钢笆面；数据变化不重置相机；
  管子按真实半径绘制，接头处保留端部间隙；钢笆显示实际裁切覆盖面，线纹同样裁切。
- **主题**：单色新拟态；控件可以有阴影，数据平面（表格、读数、画布）保持扁平 + 细线。

## 13. 规则变更流程

1. 改 `src/domain/scaffold.ts`（计算与几何只在这里）；
2. 改 `src/domain/scaffold.test.ts`，把新规则钉成回归测试；
3. 改**本文档**对应条目（含数值示例）；
4. 跑 `npm test`、`npm run lint`、`npm run build`；
5. 3D 相关改动还要在浏览器里看一眼（桌面 + 平板尺寸）。

> 现场反馈与代码不一致时，以**本文档 + 测试**为准判断当前实现，再决定改哪一边。


## 14. 路径周长与三维段长

- 二维、三维显示同一份 `layout.perimeter`：**各测量段长度之和**，单位 m，显示两位小数。
- 开口路径不补封口线；只有用户明确画出的闭合边才计入。它不是双排钢管的外包轮廓周长，
  也不包含转角延伸、管端外伸或库存钢管富余。
- `layout.pathDimensions` 保留路径顺序、测量长度及位置，二维与三维统一显示 `#段号 · 长度 m`。
- 二维标注按屏幕像素避让所有线段、节点、其他标签和画布边界，短边优先分配邻近空位；缩放时文字大小不变，标注位置不写入测量坐标。
- 三维标注平铺在地面上方 0.015 m、外排以外 1.2 m 处，沿对应线段方向放置；切换「内侧位置」时随外排换边。采用无底框的淡灰文字，世界位置、方向和尺寸固定，不随相机旋转，不参与零件拾取。
- 三维文字用本地 CanvasTexture 绘制，参数不变时复用，卸载时释放；不加载远程字体，不增加每帧计算。标签显示测量段长，不使用定尺组合长度替代。
