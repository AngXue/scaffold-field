# 规则框架回退演练

本演练在全新的隔离浏览器中执行，不接触5173、OA、用户浏览器存储或APK。冻结旧版为`803ba541f059b4e8133d1887512669743d6dcb03`；当前版取本分支的生产构建。它是网页构建的离线切换演练，不是实际线上发布或安卓降级。

## 可重复步骤

1. `npm run build`生成当前网页。
2. `node scripts/calculation-parity/prepare-rollback.mjs`从固定Git提交提取旧源码和构建依赖到临时目录。先检查旧／新锁文件完全相同，再只读复用依赖并构建；不复制覆盖工作区。记录提交、源码归档、锁文件摘要和旧构建目录，并保存可独立解压使用的`artifacts/rule-migration/rollback-release.tar.gz`网页资产包。
3. 设置`PLAYWRIGHT_MODULE`指向已安装的Playwright模块，执行`node scripts/rollback-browser.mjs`。可用`SITE_QA_OUTPUT`指定截图和完整JSON／CSV的输出目录。
4. 浏览器在同一隔离域名、同一localStorage中先载入新版，再切旧版，再恢复新版。请求直接从对应构建目录读取，不访问外部服务，不以清空存储来掩盖迁移错误。

## 固定项目与验收

| 项目 | 重点 |
| --- | --- |
| roof | 独立手算屋顶单跨，5m规格人工加2根、十字扣人工加1包 |
| stack | 父子房屋关系、顶面落脚和原层数 |
| corridor-independent | 自动跨屋顶及独立面层数设置 |
| adjacent-houses | 原双屋所有笔画及材料，允许已确认的S01排列修正 |
| narrow | 非法草图仍可保存／导出0.7，但不能导出材料CSV或打印 |
| legacy | 平地图纸、参数和材料修正 |

有效项目的人工修正通过真实材料页按钮录入。三个构建状态下逐一比较场景、参数、人工增量、完整CSV和历史记录；保存不产生重复历史。计算值和人工增量仍分别保存，不把最终显示数量写回几何。新版本实际诊断必须报告当前引擎指纹，不能误把旧网页当新网页。

每次运行记录当前／冻结构建的全部资产摘要，运行前后源码与资产不得变化；新运行开始即撤销旧通过记录。输出每个项目、每个版本的JSON、CSV和材料页截图，最终报告位于`artifacts/rule-migration/rollback.json`。GitHub回归流程同样执行这六类演练。

## 用户确认及验收边界

用户于2026-11-13明确确认：保留现有行为，默认示例不带人工修正；普通项目与历史保留修正。此项作为方案文字的明确细化登记，不更改现有产品行为。六类图分别补充默认示例的新版→旧版→新版加载：确认修正为空、图纸和参数一致、默认示例设置不修改普通已保存项目及历史。屋顶单跨普通项目显示58个十字扣（28+30），默认示例恢复为28个。

完整迁移仍需全局S0–S9、全部中间实体身份／谱系及最终生产验收。演练不会把未完成规则迁移标为完成，也不意味着旧版保留了已授权修正后的每根管位置；双屋S01的方向修正在旧构建中自然仍是旧规则，材料和保存输入不受影响。
