# 架算 Scaffold Field

架算用于扣件式钢管脚手架的现场测量和材料估算。工作流程是「三维绘图 → 三维检查 → 材料结果」。绘图使用选定标高的俯视画布，浏览和检查可旋转查看房屋与架体。

本说明对应独立网页的当前源码。规则框架正在 `codex/rule-framework` 分支实施，完整验收后合并 `main`。安卓 1.3 的设备验收另见[平板测试记录](docs/qa/1.3-平板测试.md)，本分支的平板验证采用浏览器模拟触摸，OA 使用自己的 1.3 内核。

## 快速上手

1. 用「房屋笔」画矩形，或切到「轮廓」逐点勾勒水平、垂直边，绘制时实时显示边长。点回起点闭合，或用「借墙闭合」沿已有墙边补齐后生成房屋，随后可调整高度。轮廓支持 L 形、U 形等凹形，选择已有顶面后也能叠放。体块可拖动对齐和缩放尺寸。
2. 用「脚手架笔」画水平或垂直线。沿墙边拖一笔即可吸附，内排立柱中心默认距墙 **0.30 m**；手选地面或打开缺少自动标记的旧贴墙段也会自动退墙。同一笔跨越可承托两排柱脚的顶面时，会自动分段。画布预览地面段、顶面段和同层接通区。
3. 「沿外墙围一圈」可生成整组围架；通过「整组 / 单段」切换层数修改范围，也可用「划分选段」沿已有线拖出独立区间。
4. 在「脚手架参数」设置**全局目标层数**，默认从最低地面起算到第 5 层。各面默认跟随全局。选中一面后，可关闭「跟随全局目标层数」或直接填写「本面目标层数」，独立设置会随项目和历史保存。
5. 在「三维检查」点选立杆、钢管、扣件、钢笆、槽钢或房屋体块查看规格；叠放体块用独立描边区分，「尺寸」图层可显示路径尺寸。材料结果区分计算数量与手工修正，支持 CSV 和打印。柱脚、底座或架体碰撞等阻断项可在图纸中定位，草图可照常保存。

可从「对象与测算 → 验收 Demo」载入「左侧居中走廊 · 前左相连」。全局目标 5 层时，左侧实际为 **5／4／5 层**，走廊顶两对立柱，与两侧地面端柱组成三个 **1.80 m** 跨。第 1 层在走廊处断开，两处靠实墙的横向端栏杆省去，第 2 至第 5 层接通。固定输入、操作和其他验收图纸见[三维房屋与分段测算方案](docs/三维房屋与分段测算方案.md)。

新项目默认钢笆纵向杆数为 **3**，脚手架宽度为 **0.75 m**，钢笆片为 **0.75 × 1.00 m**。已保存的明确参数继续参与原图测算。屋顶单跨等历史手算 Demo 固定使用原参数，以便复核。

## 存档与兼容

- 已保存项目优先恢复，其次是用户保存的默认示例。两者都没有时从空白图纸开始。顶栏历史最多保留 100 条记录。普通项目和历史保留人工材料修正；设为默认示例时仅保存图纸和参数，不带人工修正。
- `0.7` 项目包含房屋体块及其轮廓、脚手架笔画、参数和材料修正，兼容旧图中的辅助线。自动拆出的落脚段由笔画和场景重算。旧版平地图纸按原坐标和作业层数恢复到最低地面。
- 各段均落地且作业层数一致的平地图纸可导出 OA 兼容 `0.6` JSON，条件是图纸中没有体块和辅助线。带阻断问题的图纸可导出 `0.7` 草图，材料 CSV、打印和 `0.6` 导出在修正前暂停。

## 开发与验证

```bash
npm install
npm run dev
npm test
npm run lint
npm run build
npm run audit:geometry
npm run test:parity
npm run test:rules -- --domain-only
npm run rules:docs -- --check
```

默认开发地址为 `http://localhost:5173`。几何审计需要 Node.js 22.18 或以上，使用固定图形及变换验证平地内核。三维场景的手算、标高、兼容与交互回归分别由单元测试和 `scripts/site-browser.mjs` 覆盖。浏览器脚本的启动参数和已有结果见[三维场景网页验收](docs/qa/三维场景网页验收.md)，平地专项图册见[正交图形算法测试](docs/正交图形算法测试.md)。

## 架构与规则

| 位置 | 职责 |
| --- | --- |
| `src/components/SiteEditor.tsx` | 房屋笔、脚手架笔、选面、吸附、预览和撤销 |
| `src/domain/site.ts` | 场景解析、全局标高、几何校验和 `SiteLayout` 汇总 |
| `src/domain/siteRouting.ts`、`src/domain/siteTransitions.ts` | 沿墙偏移、自动落脚、跨高差排站和同层接通 |
| `src/domain/scaffold.ts`、`src/domain/plan.ts` | 单落脚架体、定尺组装、扣件、材料汇总和旧平地路径几何 |
| `src/domain/rules/` | 分阶段规则、冲突检查、构件来源、标准管选配与定位记录、材料贡献和诊断 |
| `src/App.tsx` | 项目与参数状态，向绘图、三维检查和材料表提供同一份 `SiteLayout` |
| `src/components/ui/`、`docs/UI组件库.md` | 新拟态组件库、设计令牌和界面规范 |
| `src/components/planAnnotations.ts`、`SceneDimensions.tsx` | 二维标注避让、三维尺寸标签与拾取辅助 |

规则框架设计见[规则框架设计](docs/规则框架设计.md)、[现有规则清单](docs/规则清单.md)和[迁移与验收方案](docs/规则框架迁移与验收.md)。方案已批准并开始实施，当前状态见[规则框架实施进度](docs/规则框架实施进度.md)；完整规则迁移尚未完成。逐项业务及组合检查见[可执行验收矩阵](docs/qa/规则验收矩阵.md)。[规则索引与依赖图](docs/规则索引与依赖图.md)由实际注册表生成；修改规则步骤后执行 `npm run rules:docs`，本地审计与GitHub检查会拒绝过期文档。

排查测算结果时，可从项目导出菜单选择「导出计算诊断」。诊断包含输入和引擎版本、实际构件合并／裁除关系、标准管选配及移动历史、钢笆裁片和底座承托／省略记录、材料贡献和问题来源；导出不会修改项目或人工数量。详细诊断按需生成，普通项目仍使用上述存档格式。

界面组件与交互口径见[UI 组件库](docs/UI组件库.md)。测算口径见[计算规则](docs/计算规则.md)。改规则时同步更新领域代码、回归测试和文档。扣件计量的历史核对见[扣件计算复核](docs/扣件计算复核.md)。安卓性能的测量方法及迁移条件见[技术栈评估](docs/技术栈评估.md)。

## 使用范围

架算估算几何和材料数量。结构承载、地基与屋面承载、连墙件、剪刀撑和专项施工方案属于独立核验范围。模型建立时参考 `GB 51210-2016`《建筑施工脚手架安全技术统一标准》和 `JGJ 130-2011`《建筑施工扣件式钢管脚手架安全技术规范》的构造关系。工程采用的标准版本、适用条件和方案由项目另行核定。
