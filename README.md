# 架算 Scaffold Field

平板优先的脚手架现场测量与材料估算 MVP。应用围绕统一的 `ScaffoldLayout` 构建，打通：

> 二维路径输入 → 参数化构件计算 → 标准管组装 → 三维人工检查 → BOM

## 已实现

- SVG 二维路径编辑器：无限画布（滚轮/双指缩放、拖拽空白平移）、节点拖动、网格/同轴吸附、路径段新增，画布几何与实际长度双向同步
- 二维和三维画布全屏模式
- 参数化计算：立杆、连续纵向水平杆、横向杆
- 固定双排立杆，钢笆纵向支承杆可独立配置为 2～4 根；增加支承杆不增加立杆，且只出现在铺设钢笆的层
- 扫地杆层（默认地面以上 0.2 m，符合 JGJ 130-2011 第 6.3.2 条）：有常规横向杆和纵向水平杆，不铺钢笆，因此不含钢笆纵向支承杆
- 作业层防护（JGJ 130-2011 第 7.3.12 条）：每侧两道栏杆（上栏杆上皮高出作业层 1.2 m、中栏杆居中），默认仅外侧（规范最低要求）；`防护栏杆侧数` 可设 2（内侧也临空时）或 0
- 搭设高度按 JGJ 130-2011 第 2.1.20 条量至**架顶栏杆上皮**，顶部作业层因此位于其下 1.2 m；各层步距自扫地杆起均分，顶层不再出现短步距
- 架顶栏杆（顶层始终设置）与端部防护（开口路径两端栏杆折返封口，JGJ 80-2016 第 4.1.1 条）
- 每对立杆下按横向杆方向布置一根槽钢底座，计入材料清单
- 标准钢管物理分段：确认的库存规格 `0.8 / 1.2 / 2 / 2.4 / 3 / 4 / 4.5 / 6 m`、对接接头与组合富余
- 管端和立杆顶端外伸参数，实际顶部由标准管组合长度决定
- 转角共享立杆去重
- Three.js 轻量三维视图：旋转、缩放、平移、自动居中、构件选择
- 立杆、纵向水平杆、横向杆、防护栏杆、钢笆、扣件和槽钢独立显隐/仅看；防护栏杆仅在此单独分层，材料清单中不单列
- 钢笆铺设层间隔、片数和覆盖面积估算
- 扣件按现场三种分别统计：十字扣、对接扣、转向扣
- 材料清单支持手动增减数量（含待定材料），并保留程序计算值以便区分
- 剪刀撑、扎丝、小垫板、支模板在材料清单中列为待定材料，数量为 `--`、不参与计算，但可手动填写
- 本地项目保存与 JSON 导出
- 材料 CSV 导出及浏览器打印/PDF
- 桌面、平板和移动端响应式布局

## 架构

核心领域模型位于 `src/domain/scaffold.ts`。二维编辑器、三维渲染器和材料视图都消费同一份计算结果，不各自维护构件数据。

```text
ScaffoldPath + Parameters
          ↓
   calculateScaffold
          ↓
    ScaffoldLayout
       ↙       ↘
3D Viewer    Material/BOM
```

## 工程构造参考

当前几何规则按扣件式钢管脚手架的一般构造关系建模，调研参考体系包括：

- `GB 51210-2016`《建筑施工脚手架安全技术统一标准》
- `JGJ 130-2011`《建筑施工扣件式钢管脚手架安全技术规范》

模型已经体现以下几何事实：画布长度和测量值使用统一比例；杆件穿过扣件连接中心并在端部留有外伸；超过单根库存管能力的立杆和纵向水平杆由标准管搭接组成；立杆保持内外双排，额外纵向支承杆均匀布置在架宽内；横向水平杆贯穿两排立杆并承托全部纵向支承杆；钢笆位于支承层；扣件与具体杆件连接点关联。

默认外伸量、搭接长度、纵向支承杆数和钢笆铺设层间隔只是估算初值，不表示自动满足上述标准。标准适用版本、地区要求、荷载、地基、开口、转角、作业层防护及专项施工方案仍须由具备资质的工程人员确认。

## 当前边界

这是规则可配置方向的产品原型。连墙件已按当前产品要求排除；剪刀撑规则暂不可靠，因此不计算、不渲染，只在材料清单保留 `--`。目前尚未实现立杆基础、安全网（密目网/平网）和结构承载力验算。结果用于现场测量和材料估算，不替代结构安全验算、正式施工设计、专项施工方案或施工图。
